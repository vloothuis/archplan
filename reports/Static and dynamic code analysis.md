# Deterministic checks make LLM code analysis usable

As of November 2026, no single technique finds most real defects. Static security scanners miss more than half of real vulnerabilities, even when several are combined. Dynamic analysis is exact, but only for the code that tests execute. Large language models (LLMs) find real bugs at scale only when an external check proves each finding. The best-supported design across all three fields is the same: a deterministic tool proposes candidates with evidence, and a model or a human judges each one against a check that can be re-run. archplan already has this shape. It holds a static model, recorded call sequences, rule-based detectors and a tool interface for agents. Its detectors target authorization and design flaws, which are the classes that code-level scanners miss most often. The main gaps are interchange detail (weakness identifiers, evidence paths), edge provenance between the static and the dynamic model, tracing for languages other than Python, and proof that its findings are precise on real repositories. This report labels each figure that the research notes took from memory, from a search snippet, or from a vendor. Figures without a label were confirmed on a primary page on 17 November 2026.

## Change history predicts defects better than code metrics do

Static analysis for quality splits into three groups. Per-file linters check one file at a time. Ruff, Pylint, ESLint, Credo and staticcheck are the mature examples for archplan's four languages (from memory, [Ruff rules](https://docs.astral.sh/ruff/rules/)). Conformance checkers compare actual imports with declared rules. import-linter, Tach, dependency-cruiser, ArchUnit and Elixir's Boundary belong here ([import-linter](https://import-linter.readthedocs.io/en/stable/contract_types/), [Boundary](https://www.github.com/sasa1977/boundary)). The third group combines dependency structure with version history. DV8 and CodeScene are the main products, and both are commercial ([Mo et al., TSE 2019](https://www.cs.drexel.edu/~yc349/papers/2019/tse2019.pdf), [Tornhill and Borg](https://arxiv.org/abs/2203.04374v1)). The notes found **no open-source tool that combines structure, change coupling and hotspots across Python, TypeScript, Go and Elixir**.

The research evidence ranks these signals clearly. Change coupling means that files change together in commits. A hotspot is code that is both complex and frequently changed. Across 19 projects, files in history-aware architecture anti-patterns were more bug-prone and change-prone, and the rates rose with the number of anti-patterns per file ([Mo et al., TSE 2019](https://www.cs.drexel.edu/~yc349/papers/2019/tse2019.pdf)). Process metrics outperformed static code metrics for defect prediction (from memory, [Rahman and Devanbu, ICSE 2013](https://dl.acm.org/doi/10.5555/2486788.2486846)). Single-snapshot metrics are weaker. Object-oriented metrics lost their apparent link to faults once class size was controlled, although later studies dispute how often this holds ([summary of El Emam et al.](https://neverworkintheory.org/2011/07/07/the-confounding-effect-of-class-size-on-the-validity-of-object-oriented-metrics.html), [Tahir et al.](https://ar5iv.labs.arxiv.org/html/2106.04687)). CodeScene reports 15 times more defects in code it rates unhealthy, but the authors work for CodeScene and no independent replication was found ([Tornhill and Borg](https://arxiv.org/abs/2203.04374v1)). Almost all of this evidence comes from Java, C# and C or C++. No study validated architecture smells on Go or Elixir.

Two cautions follow. Automatic architecture recovery by clustering has low accuracy against ground-truth architectures, so its output is a suggestion and not a fact ([Lutellier et al., ICSE 2015](https://www.cs.purdue.edu/homes/lintan/publications/archrec-icse15.pdf)). At Google, showing bug-prediction scores in code review did not change developer behaviour, because developers wanted actionable output (from memory, [Lewis et al., ICSE 2013](https://research.google/pubs/does-bug-prediction-support-human-developers-findings-from-a-google-case-study/)).

The closest mainstream product to archplan is SonarQube's Architecture feature. It recovers the current architecture and compares it with an intended one. It is limited to commercial editions and does not cover Go or Elixir ([Sonar docs](https://docs.sonarsource.com/sonarqube-server/architecture), [Sonar announcement](https://community.sonarsource.com/t/architecture-analysis-in-sonarqube-server-2026-4/186120)). The academic name for this comparison is the reflexion model, which classifies each dependency as convergence, divergence or absence (from memory, [Murphy et al.](https://ieeexplore.ieee.org/document/917525)).

The foundations under these tools have shifted. Tree-sitter (a parser generator) and SCIP (an index format for resolved symbols) are maintained and permissively licensed. SCIP has indexers for Python, TypeScript and Go, and none for Elixir ([scip-code/scip](https://github.com/scip-code/scip)). GitHub archived stack graphs in September 2025 ([ecosyste.ms](https://issues.ecosyste.ms/hosts/GitHub/repositories/github%2Fstack-graphs)). PyCG, the reference Python call-graph tool, was archived in November 2023 ([PyCG repo](https://github.com/vitsalis/PyCG)). The CodeQL engine is proprietary, and free use is tied to open-source code ([CodeQL licence](https://securitylab.github.com/tools/codeql/license)).

Static call graphs set a hard limit on any model built from them. A call graph records which function calls which. For Python, application-only graphs reach about **99% precision but only 61 to 82% recall** ([Jarvis](https://arxiv.org/html/2305.05949v5)). For JavaScript, baseline recall was 75.9%, and a dynamic pre-analysis raised it to 88.1% ([Laursen et al., PLDI 2024](https://cs.au.dk/~amoeller/papers/approx)). For Java, median recall was 88.4% ([Sui et al., ICSE 2020](https://2020.icse-conferences.org/details/icse-2020-papers/47/On-the-Recall-of-Static-Call-Graph-Construction-in-Practice)). No published accuracy figures exist for typed TypeScript, Go or Elixir call graphs. Static tools still outperform language models at building call graphs ([Venkatesh et al., EMSE 2025](https://arxiv.org/abs/2410.00603)).

## Security scanners miss most real vulnerabilities, mostly design flaws

Every practical static application security testing (SAST) engine is unsound on purpose. It trades missed flows for speed and fewer false alarms (from memory, [Livshits et al., CACM 2015](https://dl.acm.org/doi/10.1145/2644805)). Peer-reviewed studies on real vulnerabilities agree on the cost. For Python, no single tool detected more than 40% of real vulnerabilities, and eight tools combined detected 66.7% ([ICSE 2026](https://conf.researchr.org/details/icse-2026/icse-2026-research-track/30/An-Empirical-Study-on-Static-Application-Security-Testing-SAST-Tools-for-Python)). For C and C++, tools missed 47 to 80% ([Lipp et al., ISSTA 2022](https://mediatum.ub.tum.de/doc/1659728/1659728.pdf)). For JavaScript, the three best tools combined detected up to 57.6% at a precision of 0.11% ([Brito et al.](https://export.arxiv.org/abs/2301.05097)). Synthetic benchmarks overstate real performance in all of these studies. No real-world evaluation for Go or Elixir was found.

The misses are not random. In the Java study, the classes missed most often were logic, authorization and design flaws, not injection ([Li et al., ESEC/FSE 2023](https://dblp.uni-trier.de/rec/conf/sigsoft/LiCFFLLLC23.html)). Broken access control ranks first in the OWASP Top 10:2025 ([OWASP](https://top10.owasp.org/2025/0x00_2025-Introduction)). Design-level security tooling is thin. Threat-modelling tools such as pytm and Threagile need a hand-written model ([pytm](https://github.com/OWASP/pytm), [Threagile](https://github.com/Threagile/threagile)). Research on missing-authorization detection targets PHP, Rails and Spring and dates mostly from 2011 to 2019. Its most reusable idea is consistency checking: if most paths to a sensitive operation pass a guard and one does not, flag the outlier (from memory, [RoleCast](https://dl.acm.org/doi/10.1145/2048066.2048146), [MACE](https://dl.acm.org/doi/10.1145/2660267.2660337)). MITRE's CWE view 1008 catalogues weaknesses that are rooted in architecture (from memory, [CWE-1008](https://cwe.mitre.org/data/definitions/1008.html)). No benchmark of design-level security findings exists.

The tool landscape changed in ways that matter for reuse. Semgrep moved its maintained rules to a restrictive licence in December 2024, and a vendor consortium forked the engine as Opengrep ([InfoQ](https://www.infoq.com/news/2025/02/semgrep-forked-opengrep)). Opengrep 2.0.0 added cross-file taint analysis on 13 November 2026 ([Opengrep releases](https://github.com/opengrep/opengrep/releases)). Taint analysis tracks untrusted data from a source to a sensitive sink. Pyre is archived and Pysa moved to its own repository ([pyre-check](https://github.com/facebook/pyre-check)). Sobelow, the only Elixir and Phoenix security checker, has had no release since August 2023 ([Sobelow](https://github.com/nccgroup/sobelow)). Pysa, CodeQL and Semgrep share one design: a generic engine plus small data files that list sources, sinks and sanitizers per framework (from memory, [Pysa](https://pyre-check.org/docs/pysa-basics/), [CodeQL models](https://codeql.github.com/docs/codeql-language-guides/customizing-library-models-for-python/)).

Developer studies set a noise budget. Google keeps a check only when developers ignore at most about 10% of its findings (from memory, [Tricorder](https://research.google/pubs/tricorder-building-a-program-analysis-ecosystem/)). Microsoft developers tolerate roughly 15 to 20% false positives, a number quoted from a citing paper ([Christakis and Bird](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/07/ase-2016.pdf)). Meta reported a fix rate near 0% for batch bug lists and about 70% at code-review time (from memory, [Distefano et al., CACM 2019](https://dl.acm.org/doi/10.1145/3338112)).

Dependency scanning is converging on the OSV advisory format and on reachability, which reports a vulnerable dependency only when the code can call it. The independent evidence is cautious. In VEX-Bench, govulncheck failed to build 11 of 30 Go cases, and reachability tools could not judge whether a path is feasible ([VEX-Bench](https://arxiv.org/pdf/2609.08040)). The claim that reachability removes about 92% of findings is a vendor claim ([Endor Labs](https://www.endorlabs.com/use-case/sca-with-reachability)). For interchange, SARIF 2.1.0 remains the standard, and version 2.2 is not final ([OASIS](https://oasis-open.org/?p=1786), [sarif-spec](https://github.com/oasis-tcs/sarif-spec/issues/612)).

## Runtime traces are exact but only as complete as the tests

Each of archplan's languages now has a first-party event interface. Python 3.12 added `sys.monitoring`, which lets a tool switch off events per code location ([PEP 669](https://peps.python.org/pep-0669/)). No authoritative benchmark compares it with `sys.settrace` for call tracing. The only per-call figure found is from one profiler, which measured 141 ns per call on Python 3.13 ([tprof](https://adamj.eu/tech/2026/08/08/python-tprof-performance/)). Go execution tracing costs 1 to 2% CPU since Go 1.21, but it records scheduling events and not function calls ([Go blog](https://go.dev/blog/execution-traces-2024)). Erlang/OTP 27 added isolated trace sessions, which give exact call tracing with no recompilation ([OTP trace docs](https://www.erlang.org/doc/apps/kernel/trace.html)). Node.js has no first-party interface that emits every function entry and exit (from memory, [V8 blog](https://v8.dev/blog/javascript-code-coverage)). One vendor benchmark measured about 7% throughput loss for request context tracking and a drop to 18.6% of baseline with full OpenTelemetry auto-instrumentation ([Platformatic](https://blog.platformatic.dev/the-hidden-cost-of-context)).

AppMap is the closest existing product to archplan's tracer. It records one trace per test case and renders sequence diagrams, with HTTP and SQL calls as leaf events ([AppMap Python reference](https://appmap.io/docs/reference/appmap-python.html)). Research on trace-based architecture views found that standard OpenTelemetry instrumentation is not enough, because it shows service boundaries and not internal structure ([Hansen and Hasselbring](https://arxiv.org/abs/2411.12380v1)).

Static and dynamic call graphs fail in opposite ways. The static graph misses 12 to 39% of real edges in dynamic languages, as the recall figures above show. The dynamic graph misses everything on paths that no test runs. The best published result feeds runtime observations into the static analysis as hints ([Laursen et al., PLDI 2024](https://cs.au.dk/~amoeller/papers/approx)). In Python, method calls on built-in types account for 59% of callees missing from the static graph ([DyPyBench](https://arxiv.org/abs/2403.00539)).

Test adequacy evidence is contested. Coverage correlates only weakly to moderately with fault detection once suite size is controlled ([Inozemtseva and Holmes](https://cs.ubc.ca/~rtholmes/papers/icse_2014_inozemtseva.pdf)). Mutation testing changes code on purpose and checks whether a test fails. Mutant detection predicts real-fault detection better than statement coverage does ([Just et al.](https://homes.cs.washington.edu/%7Emernst/pubs/mutation-effectiveness-fse2014.pdf)). Google made it practical by mutating only changed lines and suppressing unproductive mutants, after developers first judged 85% of mutants unproductive ([Petrović et al.](https://arxiv.org/abs/2102.11378)). Single runs are unreliable. In Python projects, 59% of flaky tests depend on test order ([Gruber et al.](https://arxiv.org/abs/2101.09077)).

Security-oriented dynamic analysis has less to offer memory-safe languages. Fuzzing sends generated inputs to find failures. OSS-Fuzz has found over 13,000 vulnerabilities, mainly in memory-unsafe code ([OSS-Fuzz](https://github.com/google/oss-fuzz)). The open-source fuzzers for Python and JavaScript are weakly maintained ([Atheris](https://pypi.org/project/atheris), [Jazzer.js](https://github.com/CodeIntelligenceTesting/jazzer.js)). The productive techniques for web services are schema-driven API fuzzing and replay-based authorization checks. Schemathesis found 1.4 to 4.5 times more defects than the next-best tool, in an evaluation by its own authors ([Schemathesis paper](https://arxiv.org/abs/2112.10328)). Runtime type collection is affordable with sampling. RightTyper reports about 27% overhead ([RightTyper](https://arxiv.org/html/2507.16051v3)). No head-to-head study of bugs found by static and dynamic techniques exists for any of the four languages.

## LLM findings hold up only behind an external check

LLMs asked for a yes-or-no verdict on one function perform near chance on clean benchmarks. The older benchmarks that showed high scores had label accuracy between 25% and 60% ([PrimeVul](https://arxiv.org/html/2403.18624v2)). On paired samples, GPT-4 judged 12.94% of pairs correctly against 22.70% for random guessing ([PrimeVul](https://arxiv.org/html/2403.18624v2)). Newer models score higher on single functions, but those figures come from search snippets only ([TREAT](https://arxiv.org/pdf/2510.17163)). Detection is far harder than repair. On BountyBench, one agent scored 12.5% on detection, 47.5% on exploitation and 90% on patching ([BountyBench](https://arxiv.org/abs/2505.15216)).

Hybrid systems pair an LLM with a static analyser. Their own papers report strong results. IRIS detected 55 of 120 Java vulnerabilities against 27 for CodeQL alone (snippet only, [IRIS](https://arxiv.org/html/2405.17238v3)). An independent 2026 replication is sobering. On 24 active projects, the sampled false discovery rate was **97.0% for RepoAudit, 94.4% for IRIS, 92.3% for Semgrep and 85.3% for CodeQL** ([Li et al. 2026](https://arxiv.org/html/2601.19239v1)). The false discovery rate is the share of reported findings that are wrong. Of the false positives, 37.47% came from shallow reasoning across function boundaries. Nearly all misses by the static tools came from source and sink lists that did not match project-specific interfaces. The replication used models one to two generations behind the 2026 frontier.

Triage of analyser alerts is the best-supported LLM use. At Tencent, hybrid techniques removed 94 to 98% of false positives at USD 0.0011 to 0.12 per alarm ([Du et al.](https://arxiv.org/abs/2601.18844)). An agent with code access identified up to 93.3% of false positives among real CodeQL alerts ([Sifting the Noise](https://arxiv.org/abs/2601.22952); one of the two notes read only a snippet). The error is asymmetric and tunable. Semgrep's assistant agreed with 96% of true-positive calls and 41% of false-positive calls (vendor-reported, snippet only, [Semgrep](https://semgrep.dev/blog/2025/building-an-appsec-ai-that-security-researchers-agree-with-96-of-the-time/)). An open question such as "is this warning real?" was unreliable, and structured step-by-step checks were needed (snippet only, [BugLens](https://arxiv.org/html/2504.11711v3)).

Execution turns LLM output into proof. Without a check, one model run 100 times on a known kernel bug gave 8 correct reports and 28 false ones, and detection fell to 1 in 100 when the context grew fourfold ([Heelan](https://sean.heelan.io/2025/05/22/how-i-used-o3-to-find-cve-2025-37899/)). With a check, Anthropic reported more than 500 validated high-severity vulnerabilities with Claude Opus 4.6, restricted to bugs that a crash can confirm (vendor-reported, [Anthropic](https://www.anthropic.com/research/zero-days)). The later figure of more than 10,000 for Claude Mythos Preview is vendor-reported, read from a snippet only, and includes the model's own severity estimates ([Anthropic](https://www.anthropic.com/research/glasswing-initial-update)). In DARPA's AI Cyber Challenge, finalists found 54 of 63 synthetic vulnerabilities ([DARPA](https://darpa.mil/news/2025/aixcc-results)). The curl project ended its bug bounty in January 2026 after a surge of unverified AI-generated reports ([The Register](https://www.theregister.com/2026/01/21/curl_ends_bug_bounty/)).

The same pattern holds for quality. LLMs detect local smells such as long methods. They do poorly on smells that depend on relations between classes, unless computed metrics or dependency data are added to the prompt (snippet only, [Souza et al.](https://arxiv.org/pdf/2601.09873), [Ghadimi et al.](https://arxiv.org/pdf/2504.16027)). Review comments grounded in an explicit rule were adopted by 42% of developers against 22% for free-form comments (snippet only, [SGCR](https://arxiv.org/html/2512.17540v1)). No study measured LLM detection of architecture smells against ground truth. Conclusions about LLM triage of design findings are extrapolations from security research.

Context supply moved from pushed overviews to pulled facts. Repository context files did not improve task success and raised cost by more than 20% ([Evaluating AGENTS.md](https://arxiv.org/abs/2602.11988)). Putting all relevant files in context degraded bug fixing sharply ([arXiv 2602.16069](https://arxiv.org/html/2602.16069v1)). Code graphs help most as a query target for locating code. LocAgent reached up to 92.7% file-level localisation accuracy ([LocAgent](https://arxiv.org/abs/2503.09089)). The token savings that community code-graph servers report are vendor claims with no task-success measurement. Curated facts beat raw neighbourhoods. Abstracted data-flow context improved detection, while raw callers and callees often did not ([arXiv 2504.16877](https://arxiv.org/html/2504.16877v1), [arXiv 2604.08417](https://arxiv.org/pdf/2604.08417)).

Tool design guidance for the Model Context Protocol (MCP) comes mainly from Anthropic, a vendor. It recommends a small set of workflow-level tools, readable identifiers, a concise default with a detail switch, pagination, and errors that say how to recover ([Anthropic, writing tools](https://www.anthropic.com/engineering/writing-tools-for-agents)). Claude Code caps a tool response at 25,000 tokens by default. Deferred tool loading raised accuracy on Anthropic's own MCP evaluations from 79.5% to 88.1% with Opus 4.5 (vendor-measured, [Anthropic, advanced tool use](https://www.anthropic.com/engineering/advanced-tool-use)). Deterministic feedback improves agent output. Feeding Bandit and Pylint results back to a model cut security issues from over 40% to 13% ([arXiv 2508.14419](https://arxiv.org/abs/2508.14419v1)). GitHub's Autofix counts a fix only when the alert disappears, no new alert appears and no test outcome changes (vendor-measured, [GitHub](https://github.blog/engineering/platform-security/fixing-security-vulnerabilities-with-ai/)).

## What archplan should keep, add and prove

archplan sits in a gap. Its security detectors (open entry points, unguarded paths, trust-zone violations) target the classes that taint-based scanners miss. Its history detectors rest on the best-supported quality evidence. Its findings are rule-grounded and deterministic, which is the property that raises adoption and removes the need for LLM verification. A check of the source tree for this report showed that several recommendations in the notes are already in place. The Python tracer uses `sys.monitoring` with per-location disabling and picks a free tool id. The CI module writes SARIF 2.1.0 with fingerprints derived from finding ids. A committed baseline and a ratchet limit CI failures to new findings. At the time of the search the source had no weakness identifiers and no SARIF code flows; both were added after this report.

The table lists the changes with the strongest support. "Evidence" names the finding from the sections above.

| Priority | Change | Evidence |
|---|---|---|
| High | Label each call edge as static-only, dynamic-only or both, and record which tests produced it. Report coverage per component. Treat a missing dynamic edge as "not observed". | Static recall of 61 to 88%; dynamic results bound by coverage |
| High | Add CWE identifiers and OWASP 2021 and 2025 categories to each security finding. Write the entry-to-sink path as a SARIF code flow. | CWE is the join key; GitHub renders code flows step by step |
| High | Return each finding to agents with rule rationale, location, the evidence path with file and line per hop, and a "resolved when" condition. Phrase it as fact, not instruction. | Autofix prompt design; paths as checkable certificates; rule-grounded comments |
| High | Measure precision per detector on real repositories with human labels, and state the matching granularity. | 97% false discovery in replication against 78% precision claimed; noise budgets of 10 to 20% |
| Medium | Add outlier checks: flag a handler or path that lacks a guard its siblings have. | RoleCast and MACE use majority behaviour as the specification |
| Medium | Rank structural findings by change data. Report size next to any complexity count. Separate parent-child cycles from cycles between unrelated components. | History beats snapshots; size confounds metrics |
| Medium | Keep framework knowledge in data files with source, sink and guard lists. Publish, per language, which dynamic features are not resolved. | Pysa and CodeQL model files; most static misses come from poor specifications |
| Medium | Use runtime observations as hints for static resolution: receiver types and observed callees. | Recall rose from 75.9% to 88.1% with dynamic hints |
| Medium | Keep the full architecture out of every session. Serve scoped answers with a concise default, limits and cursors. Review the roughly 25 tools for overlap. | AGENTS.md study; 25,000-token cap; tool guidance |
| Medium | Offer hooks that report only findings introduced by the session, after edits and before the agent stops. Protect rule and target files from agent edits. | Static-analysis feedback loop; Autofix acceptance gate |
| Lower | Trace Elixir with OTP 27 trace sessions. For Go and TypeScript, start with coverage counters that confirm which predicted functions ran. | Elixir tracing needs no recompilation; Go and Node lack a cheap call hook |
| Lower | Add a reachability overlay from OSV advisories, at package level where symbol data is missing. State that it needs no build and is less precise. | VEX-Bench build failures; thin symbol data outside Go |
| Lower | Mine order and boundary rules from passing traces as candidate architecture rules, with human confirmation. Report trace divergence between runs as a finding. | Daikon-style likely invariants; 59% of flaky tests are order-dependent |

Three items from the notes deserve a negative decision. Embedding CodeQL is ruled out by its licence, and Semgrep-maintained rules are ruled out by theirs. Depending on stack graphs or PyCG is unsafe because both are archived. Competing with language servers at symbol level has low value, because coding agents already ship with them.

Phoenix is an opening. Sobelow is dormant, no SCIP indexer exists for Elixir, and archplan already parses the language. The limit is that message passing between processes is invisible to static analysis, so Elixir sequences depend on tracing more than the other languages do.

## Conclusion

The fields are converging on one architecture, and it changes how to value a tool like archplan. The scarce asset is no longer a detector or a model. It is a cheap, current, queryable set of facts with a re-runnable check attached. Stronger models raise the yield of that design more than they remove the need for it. The 2026 results that scaled to thousands of confirmed bugs all had an executable oracle, and design findings have none. For design findings, a deterministic re-check against the model is the nearest substitute, and archplan owns that check.

The evidence base has a blind spot where archplan works. No benchmark exists for design-level security findings. No study measures LLMs on architecture smells. No study validates smells, call graphs or scanners on Go or Elixir. archplan cannot borrow proof from the literature for its core claims. A labelled set of its own findings on real repositories, with acceptance and resolution rates from its finding labels, would be new evidence and the strongest support for the tool.
